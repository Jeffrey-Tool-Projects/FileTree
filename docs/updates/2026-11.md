## U-20261102-01 · 2026-11-02 · 要求 Python 3.11，不再支援 3.10 · #migration #deps #ci

- **原因**：工作區的所有套件一起把最低版本提高到 Python 3.11。Pillow 13.0.0 等安全修正版本只支援 3.11 以上，繼續支援 3.10 會讓 lock 保留有已知弱點的舊版本。
- **變更**：`requires-python` 改為 `>=3.11`，移除 3.10 classifier；CI 矩陣從 3.11 開始；文件中寫著 3.10 的最低版本改為 3.11。
- **Lock**：
  - `.github/requirements/runtime.txt`: regenerated for 3.11; dropped 3.10-only entries: `tomli`.
  - `.github/requirements/test.txt`: regenerated for 3.11; dropped 3.10-only entries: `exceptiongroup`, `tomli`, `typing-extensions`.
- **其他**：`test.txt` 與 `runtime.txt` 依 `architecture.md` 記錄的指令重新產生，只移除 3.10 專用條目；ruff 目標改為 py311。
- **Lint**：ruff 改以 py311 為目標後會啟用新規則：`timezone.utc` 改成 `datetime.UTC`（UP017）；UP042（`StrEnum`）先忽略，因為改用 `StrEnum` 會改變 `str()` 的輸出。
- **待辦**：無。

## U-20261114-01 · 2026-11-14 · 新增唯讀的「實體磁碟」檢視 · #done #gui #disks #i18n

- **原因**：使用者要求完整的硬碟管理功能；這是第一部分。此項不是 `progress.md` 既有項目。
- **變更**：
  - `core.disks` 以單一提供者函式唯讀讀取實體磁碟與分割區：Windows 使用固定內容、不經 shell 的 System32 PowerShell 儲存查詢（60 秒逾時、輸出上限 8 MiB），Linux 使用 `lsblk`／`/sys/block`，macOS 使用 `diskutil`。解析函式為純函式；不保留序號，系統未回報的欄位維持未知。
  - 「檢視 → 實體磁碟…」顯示型號、SSD／硬碟、連接方式、分割表、大小、健康狀態與白話說明、溫度／耗損／通電時數（有回報時）、依比例的分割區長條與表格。查詢在背景工作中執行，掃描進行中停用。
  - `open_system_tool` 新增固定項目：磁碟管理、最佳化磁碟機、磁碟與磁碟區設定。FileTree 本身不格式化、不分割、不變更磁碟。
  - 五種語言新增 69 個字串；README、使用指南與 `architecture.md` 同步更新。主視窗截圖未受影響，未重新產生。
- **檔案**：`je_file_tree/core/disks.py`、`je_file_tree/gui/disks_dialog.py`、`je_file_tree/gui/main_window.py`、`je_file_tree/gui/system_files.py`、`je_file_tree/gui/strings.py`、`test/test_disks.py`、`test/test_disks_gui.py`。
- **量測**：本機筆電上 Windows 查詢約 6.0 秒，主要是載入 Storage 模組。
- **限制**：未以系統管理員執行時部分計數器無法取得（會說明原因，不要求提升權限）；Linux 的健康狀態為未知；工具按鈕僅限 Windows；分割區類型名稱來自作業系統，不翻譯。
- **驗證**：整套 pytest 與 `ruff check .` 通過。測試只使用自製的範例輸出，不讀取本機磁碟。
- **待辦**：無。
