## U-20261125-01 · 2026-11-25 · 新增「文字大小」設定，使用說明改用較大的文字 · #feature #gui #i18n #accessibility

- **原因**：使用者反映使用說明的文字太小，並要求能調整介面文字大小。
- **變更**：
  - **檢視 → 文字大小**：90、100、110、125、150、175、200%，立即套用到所有分頁與開啟中的視窗並記住；快速鍵 Ctrl++（或 Ctrl+=）、Ctrl+-、Ctrl+0。五種語言都有對應字串。
  - **使用說明**：文字是一般標籤的 1.3 倍、行距 145%，視窗由 640×560 改為 820×680；視窗內也有放大、縮小、恢復系統大小三個指令，快速鍵相同。說明內容新增對應的快速鍵與提示。
  - **跟著文字調整的版面**：清單欄寬與列高、樹狀圖卡片、長條圖數值、方塊圖標籤門檻、歷史圖座標、導覽列寬度、路徑列高度、窄版面的切換寬度；`fit_window` 讓新開的視窗變大，但不超過螢幕。100% 時所有數值與以前相同。
  - **結果頁可捲動**（`gui/scrolling_page.py`）：結果頁的最小高度以前就是視窗的最小高度，在可用高度 672 的螢幕上（1920×1080、顯示縮放 150%），100% 就要 786，200% 要 1129，視窗下半部會超出螢幕。現在放得下時版面不變，放不下時出現捲軸。
- **過程中發現**：
  - Qt 把新的應用程式字型排入佇列才送到視窗，依字型計算的列高會慢一步；改為先送達再計算。
  - `QScrollArea.setWidgetResizable` 對會換行的內容採用偏好高度，1200×800 原本放得下也會出現捲軸；改為只依最小尺寸決定。
- **驗證**（Windows 11、繁體中文、實際平台算繪，未顯示視窗）：
  - 切換大小的套用時間 21–50 ms。
  - 200% 時，22 個對話框的最小高度都不超過 659（可用高度 672）；主視窗在七種大小、七個結果分頁都維持在 680。
  - 1200×800 的主視窗與變更前的 README 截圖版面相同，因此沒有更換截圖。
  - 新增 21 個測試（`test_text_size.py`、`test_scrolling_page.py`）。
  - 相關的 GUI、分層與 README 對照測試檔案：1,723 個通過、5 個略過、1 個失敗（已知的 Windows 長路徑限制 WinError 206；改用較短的暫存路徑後通過）；`ruff check .` 通過。
- **未驗證**：macOS 與 Linux 只由 CI 的 offscreen 測試涵蓋，沒有看過實際畫面；系統高對比模式沿用原生樣式，未另外檢查。
- **檔案**：`je_file_tree/gui/text_scale.py`、`text_size.py`、`scrolling_page.py`（新）；`help_dialog.py`、`locale_font.py`、`window_fit.py`、`app.py`、`main_window.py`、`strings.py`，以及使用固定欄寬或文字尺寸的清單、圖表與對話框；`README.md`、`docs/guide.md` 與各四個翻譯；`architecture.md`。
- **待辦**：無。

## U-20261125-02 · 2026-11-25 · 提高淺色與深色主題的對比，重畫核取方塊與箭頭 · #feature #gui #theme #accessibility

- **原因**：使用者要求提高介面顏色的對比。
- **變更**（深色／淺色，對比值以 WCAG 公式計算，舊 → 新）：

  - **無法使用的文字**（對卡片）：深色 3.6 → 5.9；淺色 3.5 → 5.7。
  - **按鈕與輸入欄的邊框**（對卡片）：深色 1.3（下緣 1.9）→ 4.8；淺色 1.3（下緣 1.7）→ 4.5。
  - **卡片、表格與分隔線**（對卡片）：深色 1.3 → 2.2；淺色 1.3 → 2.2。
  - **捲軸**（對卡片）：深色 3.3 → 6.3；淺色 2.4 → 4.5。
  - 連結、成功與注意的文字由 4.5 提高為至少 7；選取底色在文字維持 7:1（淺色 8.5:1）的前提下取最深的強調色。
  - 選取的導覽項目、選單項目、切換按鈕與分頁改用選取底色或強調色標示（以前切換按鈕的「已選」和底色只差 1.1 倍）。
  - **核取方塊、選項按鈕、選單勾選、數字欄與下拉箭頭**：Fusion 在深色主題畫的外框看不見，數字欄箭頭只有兩像素。改由 `gui/glyphs.py` 在啟動時畫好，登錄為記憶體中的 Qt 資源，不含圖檔，也不寫入磁碟。
  - **比例長條**：改為不透明的顏色，逐步淡化到上面的數字可讀為止（淺色 7:1、深色 4.5:1）；以前深色約 3.2。
  - **圖表與建議的顏色**：影片、壓縮檔、其他、「先確認」、「自行決定」、「尚未判斷」調整為對淺色與深色卡片都至少 3:1。
- **規則**：門檻寫在 `fluent_style.py`（`TEXT_CONTRAST` 等），測試對 8 種強調色、兩種主題逐一檢查。
- **效能**：曾試過覆寫 `QProxyStyle.drawPrimitive`，每次重繪約 900 次呼叫，2 次配對中樹狀清單慢 12 與 43 ms（各取最小值），因此改用樣式表。樣式表版與變更前交錯量測 3 次，中位數 220／245／212 ms 對 272／241／197 ms，差異在雜訊內（機器同時有其他負載）。
- **過程中發現**：`qRegisterResourceData` 不複製資料，Python 的 bytes 被回收會讓程式當掉；改為保留參考。
- **驗證**：深色與淺色各看過歡迎頁、三個結果分頁與選單的原生算繪；README 截圖以 100% 縮放重新產生（1200×800）。相關的 GUI 與分層測試 1,754 個通過、5 個略過；`ruff check .` 通過。
- **未驗證**：macOS 與 Linux 的實際畫面；系統高對比模式沿用原生樣式，沒有變更。
